# セットアップ

セットアップは、プロジェクトを何もない状態から生成された設定プロファイルまで一気に連れていきます。

**Tools → WaggleBum → WagSettings → Setup** — [エディターウィンドウ](EditorWindow.md)の Setup ページです。
選択、プレビュー、Generate はここにあります。プロジェクトに何があるか、その後に手作業で残るものは、隣の
**Summary** ページにあります。このページは両方を扱います。

## 手順の連なりではなく、1 つの画面

選択肢は一度に見渡せるほど少なく、それぞれにプロジェクトが実際に持つものから導いた既定値があり、変更に応じて
プレビューが更新されます。つまり**選択の結果が、選んでいるその場で見える**のです。数クリック後ではなく。

![Setup ページ: カテゴリ、メニューと永続化の選択、プレビュー、Generate](../Images/editor-window-setup.png)

また、**再び開く**ことを前提にしています。生成は冪等なので、3 か月後に戻ってきてカテゴリを 1 つ足すのが普通の
ケースであって、やり直しではありません。ウィザードは一回限りを暗示しますが、これは戻ってくるパネルです。

すべてが一度に報告されます。段階的なフローは最初の問題を見せ、それが解決するまで 2 つ目を隠します。1 つの画面
なら、生成が拒否される理由をすべて列挙する余裕があります。

## プロジェクト — Summary ページ

Summary はまずプロジェクトが実際に持つものを見て、それぞれの結果がこれから生成するセットアップにとって何を
意味するかを述べます。

![警告と Package Manager ボタンのある Project セクション](../Images/summary-project-checks.png)

| チェック | 報告内容 |
|---|---|
| Unity バージョン | エディターが 2022.3 以降か |
| レンダーパイプライン | Built-in、URP、HDRP、カスタム — そしてそれによりどのグラフィックス設定が使えるか |
| UI フレームワーク | UI Toolkit と uGUI が利用可能か |
| Input System | コントロールのリバインドが利用可能か |
| TextMeshPro | uGUI メニューが TMP テキストを使えるか |
| 永続化 | WagSave がインストールされているか、それとも設定は PlayerPrefs を使うか |

### 重大度は慎重に選ばれる

WagSettings は単独で動くので、**プロジェクトの状態がセットアップを本当に阻むことはほとんどありません**。
パッケージが欠けても失うのは機能であり、メニューではありません。

- **Pass** — 何もすることはない。
- **Warning** — 何かが欠けているが、セットアップは続く。Input System がなければリバインドはないが、ほかはすべて動く。
- **Blocker** — 生成するものが何もなくなる。該当するのは 2 つだけ: 2022.3 より古いエディターと、UI Toolkit も
  uGUI もない状態。後者ではメニューを作る手段がまったくない。

**Warning は Generate を無効にしません。** 任意のパッケージをブロッカーにすると、このセクションを無視する癖が
つき、本当のブロッカーを見逃すことになります。

WagSave がないのは**pass**であって欠点ではありません — PlayerPrefs で単独で動くのが設計です。後で
インストールすれば、ここで何も変えずに設定が自らアップグレードします。

### ワンクリック修正

修正できる結果には、Package Manager を通じてパッケージをインストールするボタンが付きます。インストールが
終わると画面は再スキャンします。新しいパッケージのアセンブリが存在して初めてチェックが意味を持つからです。

ブロッカーには必ず先へ進む道があります — 修正のないブロッカーは行き止まりになるので、UI フレームワークの
ブロッカーがインストールを提供することを検証するテストがあります。Summary ページはインストールの進行を表示します。

**再スキャンはプロジェクトが持つものを更新し、あなたが決めたことは更新しません。** パッケージをインストールして
再スキャンしても、選択が黙って元に戻ることはありません。

## 生成する設定

各カテゴリは設定アセットのグループとメニューのタブになります。すべてのカテゴリが既定でオンですが、Input System が
ない場合の Controls は例外です — 動作しないリバインドのセクションを生成するのは、省くより悪いからです。

| カテゴリ | 設定 |
|---|---|
| Audio | マスター、音楽、SFX の音量、ミュート |
| Display | 幅、高さ、リフレッシュレート、ウィンドウモード、VSync |
| Graphics | 品質ティア、ガンマ、ブルーム、アンビエントオクルージョン、モーションブラー |
| Accessibility | UI スケール、色覚プリセット、モーション削減、字幕のスケールと背景 |
| Controls | リバインド、感度、Y 反転 |

各カテゴリの行は追加する設定の数を示すので、結果の大きさは生成後ではなく生成前に見えます。

## メニューと永続化

| 選択 | 既定 | 影響 |
|---|---|---|
| UI フレームワーク | 利用可能なら UI Toolkit、そうでなければ uGUI | 完了時の手順がどのメニューコンポーネントを追加するよう案内するか |
| 永続化 | Automatic | 生成されたプロファイルに書き込まれる |
| オーディオミキサー | テンプレートから作成 | ミキサーを生成するか — Audio にチェックがある間だけ表示 |

`Automatic` は WagSave がインストールされていれば WagSave に、なければ PlayerPrefs に解決されるので、通常ここで
選ぶものはありません。`PlayerPrefs` は WagSave を持つプロジェクトでもシンプルなストアを強制します。

### オーディオミキサー

音量スライダーには公開パラメーターを持つ `AudioMixer` が必要で、パラメーターの公開は人が見落とす手順です。
そこでセットアップは**ミキサーテンプレート** — `MasterVolume`、`MusicVolume`、`SfxVolume` を公開した Master、
Music、SFX グループ — を同梱し、生成フォルダーに `WagSettingsMixer.mixer` としてクローンします。

テンプレート、生成されるオーディオ設定、`AudioMixerApplier` の既定のバスは一致するように書かれており、テストが
それらを結び付けています。Audio Mixer Applier を追加し、生成されたミキサーを割り当てれば、すべての既定バスが
手入力なしに設定とパラメーターを見つけます。

**Use an existing mixer** は何も書きません。ミキサーはあなたのものです。そこに `MasterVolume`、`MusicVolume`、
`SfxVolume` を公開するか、アプライヤーのバス名をすでに公開されているものに変えてください。ミキサーを選ばずに
これを選ぶのは Generate が拒否することの 1 つです。

クローンはほかの生成アセットと同様に追跡されます。再実行ではスキップされ、ミキサーウィンドウでの編集は保持され、
後のパッケージバージョンのより新しいテンプレートは更新として表示されます — 適用されるのは手を付けていない
クローンに対してだけです。

`AudioMixer` には公開の作成 API がないため、構築ではなくクローンなのです。テンプレートは一度作成してコミット
されており、パッケージはそれをコピーするだけです。

## 拒否されるもの、その理由

以下のいずれかが成り立つ間 Generate は無効になり、満たされない理由が**すべて**ボタンの上に列挙されます。

- **UI フレームワーク** — パッケージをインストールせずに uGUI を選ぶ。メニューが開けません。
- **カテゴリ** — 何も選ばない、または Input System なしで Controls を選ぶ。
- **オーディオミキサー** — 「既存のミキサーを使う」でミキサーを選ばない。
- **プロジェクト** — ブロッカー。つまり生成するものがまったくない。

永続化が拒否することはありません。`Automatic` はすでに PlayerPrefs にフォールバックします。

すべてのアセットが最新で、プレビューがやることはないと言うときも Generate は無効です。

## プレビューと生成

**何が起きるかを正確に見るまで、何も書き込まれません。** プレビューはすべてのアセットとそれに何が起きるかを
列挙し、選択を変えると更新されます。

![Generate が作成・更新・保持するものを一覧するプレビュー](../Images/setup-preview-plan.png)

```
Into Assets/WagSettings/Resources

Create   Assets/WagSettings/Resources/AudioMaster.asset
Update   Assets/WagSettings/Resources/WagSettingsProfile.asset
Skip     Assets/WagSettings/Resources/AudioMusic.asset  (already up to date)
Keep     Assets/WagSettings/Resources/AudioSfx.asset  (edited since it was generated)
```

Generate ボタンの隣の一行の要約は常に表示されるので、詳細は必要になるまで畳んでおけます。

### 再実行は安全

セットアップは、生成したすべてのアセットと書き込んだ内容の指紋を記録する**生成マニフェスト**を保持します。
これにより 3 つのケースを区別できます。

| 状況 | 起きること |
|---|---|
| アセットが存在しない | **Create** |
| セットアップが作り、誰も触っていない | 設定が変わっていれば **Update**、そうでなければ **Skip** |
| セットアップが作り、その後編集された | **Keep** — そのまま残す |
| そのパスにすでに別のものがある | **Keep** — セットアップが上書きするものではない |

つまりカテゴリを追加してから再生成すると、新しいアセットだけが作られます。**生成された既定値の手調整が捨てられる
ことはありません。** 生成されたアセットを削除すれば、セットアップはもう一度作ることを提案します。

### 生成が失敗したら

生成は 1 つの `AssetDatabase` トランザクションとして実行されます。途中で何かが例外を投げると、その実行で作られた
すべてのアセットはエラーが表面化する前に削除されます — 半分だけ生成されたプロジェクトは、何もないより
悪いからです。トランザクションは `finally` で閉じられるので、失敗がセッションの残りの間アセットデータベースを
一時停止したままにすることはありません。

作られたアセットは `Undo` に登録されるので、<kbd>Ctrl</kbd>+<kbd>Z</kbd> が効きます。

### 生成フォルダーが Resources フォルダーである理由

`Assets/WagSettings/Resources` は名前の偶然ではありません。Resources フォルダーにある `SettingsProfile` は
`WagSettingsBootstrapper` が起動時に探すものなので、セットアップを実行したプロジェクトは、どのシーンにも何も
置かずに動作する `WagSettingsManager` — そして動作する静的 API — を得ます。生成されたプロファイルには
**Is Default** のフラグが立つので、同じフォルダーに別のプロファイルがあっても優先されます。エディター側の記録である
生成マニフェストは、ビルドに含めないようマークされています。

### 実行後

エディターは **Summary** に移動し、書き込まれたものを、生成されたプロファイル、生成フォルダー、Quick Start
シーン、チートシートへのボタンとともに表示します。手作業で残る手順はそのページのドキュメントペインにあり、
いつ戻っても参照できます。調整して再生成するには Setup に戻ってください。

![生成後の Summary ページとショートカットボタン](../Images/summary-after-generate.png)

## まだ生成されないもの

セットアップは**設定アセット、それらを保持するプロファイル、オーディオミキサー**を生成します。InputActionAsset の
作成やビジュアルスタイルプリセットの適用はまだ行わないので、それらのコントロールは表示されません。`StyleRule`
ルール、`WiringRule` の入力アクション側の半分、およびそれらのモデルフィールドは、生成が対応する日に備えて
存在しています。

当面は入力アクションを手で配線してください。[コントロール](Settings/Controls.md)を参照してください。

## Setup へのたどり着き方

| 経路 | いつ |
|---|---|
| **Tools → WaggleBum → WagSettings → Setup** | いつでも — Setup ページでエディターを開く |
| エディターのレールの **Setup** ページ | エディターが開いているとき |
| Scene ビューのオーバーレイ | Scene ビューのオーバーレイメニューから「WagSettings」を有効にする |
| 自動で、一度だけ | インストール後にエディターが最初に読み込まれたとき |

### 自分で開くことについて

セットアップは**一度だけ**自分を提示し、二度としません。ドメインリロードのたびにウィンドウを開き直すアセットは
アンインストールされるので、答えは現れた瞬間に記憶されます — すぐに閉じても提示済みと数えられます。

この印はパッケージバージョンごとに保存されるので、メジャーアップグレードではもう一度自己紹介するかもしれません。
バージョンを判定できない場合はまったく開きません。記録先のないバージョンでは、リロードのたびに尋ねることに
なるからです。

Scene ビューのオーバーレイは**既定で非表示**です。誰かの Scene ビューに恒久的に居座るパッケージは越権です。
欲しい人のためにオーバーレイメニューにあります。

## 組み立て方

各ページは 1 つの `SetupSession` の上のシェルで、共有されているので Summary と Setup を切り替えてもスキャンも
選択も失われません。プロジェクトが持つものは `EnvironmentDetector`、選んだものは `SetupModel`、生成できるかは
`ISetupRule` のリストの上の `SetupValidation`、書き込まれるものは `SettingsGenerator` — すべてエディターウィンドウに
依存しない素のクラスなので、すべてのルールが直接テストされます。

ルールは `IsSatisfied(model, out reason)` に答えます。UI を持たないので、Generate ボタンをグレーアウトする同じ
条件が、テストでは 2 行のアサーションになります。

検出は `IEnvironmentProbe` を通じて生の事実を読むので、「サポート外のエディターで Input System のない HDRP」の
ようなシナリオは、プロジェクト丸ごとではなく 2 行のテストです。任意のパッケージはすべて参照ではなく名前で型を
探して見つけます。ここで URP や Input System を参照すると、まさにセットアップが助けるべきプロジェクトで
コンパイルに失敗するからです。

Setup ページはコントロールの再構築と、そこから導かれるものの更新を分けています。セッションは `Changed` とは別に
`Scanned` を発生させるので、チェックボックスを入れてもそのチェックボックス自体が再構築されることはありません —
設定メニューは、すべての行を再構築してドラッグ中のフォーカスを失った苦い経験からこれを学びました。
