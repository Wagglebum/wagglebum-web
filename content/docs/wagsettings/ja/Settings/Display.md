# ディスプレイ

解像度、リフレッシュレート、ウィンドウモード、VSync、モニターの選択。これらは **Apply ボタン**で適用され、
プレイヤーがドロップダウンをスクロールしている間には適用されません — スクロール中のウィンドウのリサイズは、
設定メニューを壊れているように感じさせる類のものです。

## 解像度はインデックスではなく解像度として保存される

ほとんどの設定メニューは「ドロップダウンの 3 番目の項目」を保存します。WagSettings は実際の幅、高さ、リフレッシュ
レートを保存します。ハードウェアが変わった瞬間、インデックスは別のものを意味するからです。

- プレイヤーがラップトップをドックする、または外部モニターを抜く
- セーブを別のマシンや携帯機に移す
- ドライバー更新で報告されるモードが変わる

1920×1080 を指していたインデックスが、今は 800×600 を指します。実際の値はそのすべてを生き延びます。

トレードオフは、保存されたモードが目の前のマシンに存在しないかもしれないことです。`DisplayModeMatcher` が
それを解決します。**ピクセル寸法が優先され、リフレッシュレートが同点を決め**、最も近い対応モードが勝ちます。
ゲームは解像度のせいで起動を拒んではならないので、これは**例外を投げずに警告します** — 下の
*例外を投げるもの、警告だけのもの* を参照してください。

```csharp
var desired  = new DisplayMode(1600, 900, 60);          // not supported here
var resolved = DisplayModeMatcher.FindNearest(applier.AvailableModes, desired);  // 1920 x 1080 @ 60 Hz
```

保存されたリフレッシュレート `0` は**「このディスプレイが提供する最高値」**を意味し、一度も設定されたことのない
ゲームには正しい既定です。

## 設定

すべてのキーは任意です。空にしておけば、アプライヤーはその側面を管理しないので、ウィンドウモードのトグルだけが
欲しいプロジェクトはまさにそれを持てます。

| 設定 | 型 | キー | 注記 |
|---|---|---|---|
| 幅 | `IntSetting` | `display.width` | ピクセル。高さのキーも必要。 |
| 高さ | `IntSetting` | `display.height` | ピクセル。幅のキーも必要。 |
| リフレッシュレート | `IntSetting` | `display.refreshRate` | Hz。`0` は利用可能な最高値。 |
| ウィンドウモード | `IntSetting` / `EnumSetting` | `display.windowMode` | `0` ウィンドウ、`1` ボーダーレス、`2` フルスクリーン。 |
| VSync | `IntSetting` / `EnumSetting` | `display.vsync` | `0` オフ、`1` 毎ブランク、`2` 1 つおきのブランク。0–2 に丸める。 |
| モニター | `IntSetting` | `display.monitor` | 0 始まりのディスプレイインデックス。**オプトイン**: モニター間でウィンドウを移動するのは選択にすべきほど破壊的なので、アプライヤーのキーは既定で空で、セットアップも生成しない。 |

`WindowMode` は Unity の `FullScreenMode` ではなく WagSettings の列挙型です。この 3 つはプレイヤーが理解する
選択肢で、番号付けは Unity のバージョン間で安定し、値はセーブデータに入ります。

## セットアップ

1. 上の設定を作り、`SettingsProfile` に追加する。
2. **Add Component → WaggleBum → WagSettings → Resolution Applier**。キーは慣例の名前で事前に埋まっています。管理
   したくないものは空にしてください。
3. **WagSettings Manager** の下に置く。マネージャーが起動時に接続します。あるいは Display にチェックを入れて
   Setup を実行し、手順 1 と 2 を飛ばしてください。

## 解像度ドロップダウン

どちらのメニューも幅、高さ、リフレッシュレートを**ディスプレイが対応するモードの 1 つのドロップダウン**として
表示します — `1920 × 1080 @ 144 Hz`、`1920 × 1080 @ 60 Hz` など、最も広いものから。これが 3 つの設定の上の複合体
`ResolutionBinder` です。メニューは `ScreenModes.Query()` にハードウェアが何をできるかを尋ね、リストを
`SettingBinderFactory.CreateAll(registry, modes)` に渡します。これは 3 つを、プロファイルで `display.width` が
あった場所に立つ 1 つのバインダーにまとめます。「resolution」を検索すれば見つかります。

![ディスプレイのモードを一覧する解像度ドロップダウン](../../Images/resolution-dropdown.png)

プレイヤーが見るのは 1 つの選択です。ストアが見るのは依然として 3 つの数で、それが上のセクションの要点です。
モードリストへの保存されたインデックスは次のモニターでは別のものを意味しますが、`1920 × 1080` はそうでは
ありません。

保存された値がディスプレイのできる何にも一致しなければ — 大きなモニターから持ち越された設定 — ドロップダウンは
黙ってスナップせず **Custom: 2560 × 1440 @ 165 Hz** を先頭に置き、アプライヤーは適用時に依然として最も近いモードを
選びます。実在のモードを選べばカスタム項目は消えます。

プロファイルに `display.refreshRate` 設定がなければ、リストはサイズだけで、レートによる重複は畳まれます。

### プラットフォームがモードを報告しないとき

一部のプラットフォームは空の `Screen.resolutions` を返します — **macOS Editor がそうで**、WebGL もそうです。
放置するとドロップダウンには提供するものがなく、アプライヤーにはスナップする先がなく、Editor では解像度の
変化を決して見られません。そこで `ScreenModes.Query()` は、現在のディスプレイ以下の一般的な 16:9 と 16:10 の
サイズに、それぞれディスプレイのリフレッシュレートを付け、ディスプレイ自身を先頭にしてフォールバックします。
モードを報告するプラットフォームのビルドは実際のリストを使います。フォールバックは、さもなければ無反応な
場所でメニューを試せるようにするものです。

### 手作業で行う

どちらのメニューも使わないなら、同じ部品はあなたのものです。

```csharp
var binder = new ResolutionBinder(width, height, refreshRate, ScreenModes.Query());

foreach (string option in binder.Options) { /* add to your control */ }
binder.Select(index);                       // writes width, height and refresh rate
```

または同じリストである `applier.AvailableModes` から自分で部品を書いてください。

```csharp
width.Set(mode.Width);
height.Set(mode.Height);
refreshRate.Set(mode.RoundedRefreshRate);
```

アプライヤーのリストはキャッシュされます。ゲーム実行中にディスプレイが接続されたら `RefreshAvailableModes()` を
呼んでください。

## 例外を投げるもの、警告だけのもの

ディスプレイ設定はプレイヤーに非がなくても間違いになりやすいものなので、区分は意図的です。**開発者の間違いは
例外を投げ、ハードウェアの不一致は警告します。**

| 状況 | 結果 |
|---|---|
| 高さのキーなしに幅のキーを設定、またはその逆 | **例外** — 開発者だけが直せる設定エラー |
| プロファイルにないキー | **例外** — `KeyNotFoundException` |
| 保存されたモードにこのディスプレイが対応しない | **警告**し、最も近い対応モードを適用 |
| 保存されたウィンドウモードが認識できる値でない | **警告**し、ウィンドウにフォールバック |
| 選んだモニターが接続されていない | **警告**し、ウィンドウをそのままにする |
| プラットフォームがモードをまったく報告しない | **警告**し、解像度に触れない |

開発中に見るには警告を購読してください。

```csharp
WagSettingsLog.WarningLogged += message => Debug.LogWarning(message);
```

## 適用モード

既定は `OnApply` です。`Immediate` に変えると、解像度フィールドのすべてのキー入力でウィンドウがリサイズされ、
それはめったに望むものではありません — [拡張性](../Extensibility.md)を参照してください。

VSync とモニターの選択も同じスケジュールで適用されることに注意してください。VSync を即座に切り替えたければ、
`Immediate` に設定した独自のアプライヤーを与えてください。
