# 셋업

셋업은 프로젝트를 아무것도 없는 상태에서 생성된 설정 프로필까지 한 번에 데려갑니다.

**Tools → WaggleBum → WagSettings → Setup** — [에디터 창](EditorWindow.md)의 Setup 페이지입니다. 선택, 미리보기,
Generate가 여기에 있습니다. 프로젝트에 무엇이 있는지, 그 후에 손으로 할 일이 무엇이 남는지는 옆의 **Summary**
페이지에 있습니다. 이 페이지는 둘 다 다룹니다.

## 단계의 연속이 아닌 화면 하나

선택지는 한눈에 볼 수 있을 만큼 적고, 각각 프로젝트가 실제로 가진 것에서 파생된 기본값이 있으며, 바뀌는 대로
미리보기가 갱신됩니다. 즉 **선택의 결과가 선택하는 동안 보입니다**. 몇 번의 클릭 뒤가 아니라.

![Setup 페이지: 카테고리, 메뉴와 영속성 선택, 미리보기, Generate](../Images/editor-window-setup.png)

또한 **다시 열도록** 만들어졌습니다. 생성은 멱등이므로 석 달 뒤에 돌아와 카테고리를 추가하는 것이 재시작이 아닌
정상적인 경우입니다. 마법사는 한 번뿐임을 암시하지만, 이것은 돌아오는 패널입니다.

모든 것이 한꺼번에 보고됩니다. 단계별 흐름은 첫 번째 문제를 보여주고 그것이 해결될 때까지 두 번째를 숨깁니다.
화면 하나는 생성이 거부되는 모든 이유를 나열할 여유가 있습니다.

## 프로젝트 — Summary 페이지

Summary는 프로젝트가 실제로 가진 것을 보는 것으로 시작해, 각 결과가 생성하려는 셋업에 어떤 의미인지 말합니다.

![경고와 Package Manager 버튼이 있는 Project 섹션](../Images/summary-project-checks.png)

| 검사 | 보고 내용 |
|---|---|
| Unity 버전 | 에디터가 2022.3 이상인지 |
| 렌더 파이프라인 | Built-in, URP, HDRP 또는 커스텀 — 그리고 그에 따라 어떤 그래픽 설정이 가능한지 |
| UI 프레임워크 | UI Toolkit과 uGUI를 사용할 수 있는지 |
| Input System | 컨트롤 리바인딩이 가능한지 |
| TextMeshPro | uGUI 메뉴가 TMP 텍스트를 쓸 수 있는지 |
| 영속성 | WagSave가 설치되어 있는지, 아니면 설정이 PlayerPrefs를 쓸지 |

### 심각도는 신중하게 정해짐

WagSettings는 홀로 동작하므로 **프로젝트에 관한 거의 어떤 것도 셋업을 진짜로 막지 못합니다**. 빠진 패키지는
기능 하나를 잃게 하지, 메뉴를 잃게 하지 않습니다.

- **Pass** — 할 일 없음.
- **Warning** — 무언가 빠졌지만 셋업은 계속됩니다. Input System이 없으면 리바인딩이 없을 뿐, 나머지는 모두
  동작합니다.
- **Blocker** — 생성할 것이 없어집니다. 두 가지만 해당합니다. 2022.3보다 오래된 에디터, 그리고 UI Toolkit도
  uGUI도 없어서 메뉴를 만들 방법이 전혀 없는 경우.

**Warning은 Generate를 비활성화하지 않습니다.** 선택적 패키지를 블로커로 표시하면 이 섹션을 무시하도록
길들여지고, 그때 진짜 블로커를 놓치게 됩니다.

WagSave가 없는 것은 **pass**이지 결함이 아닙니다 — PlayerPrefs로 홀로 서는 것이 설계입니다. 나중에 설치하면
여기서 아무것도 바꾸지 않아도 설정이 스스로 업그레이드됩니다.

### 원클릭 수정

수정할 수 있는 결과에는 Package Manager를 통해 패키지를 설치하는 버튼이 있습니다. 설치가 끝나면 화면이 다시
스캔합니다. 새 패키지의 어셈블리가 존재해야 검사가 의미를 갖기 때문입니다.

블로커는 항상 나아갈 길을 제시합니다 — 수정 없는 블로커는 막다른 길이므로, UI 프레임워크 블로커가 설치를
제안하는지 검증하는 테스트가 있습니다. Summary 페이지는 설치 진행 상황을 표시합니다.

**재스캔은 프로젝트가 가진 것을 새로 고치지, 당신이 결정한 것을 새로 고치지 않습니다.** 패키지를 설치하고
재스캔해도 선택이 조용히 되돌아가지 않습니다.

## 생성할 설정

각 카테고리는 설정 에셋 그룹과 메뉴의 탭이 됩니다. 모든 카테고리가 기본으로 켜져 있지만, Input System이 없을
때의 Controls는 예외입니다 — 동작할 수 없는 리바인딩 섹션을 생성하는 것은 빼는 것보다 나쁩니다.

| 카테고리 | 설정 |
|---|---|
| Audio | 마스터, 음악, SFX 볼륨, 음소거 |
| Display | 너비, 높이, 주사율, 창 모드, VSync |
| Graphics | 품질 티어, 감마, 블룸, 앰비언트 오클루전, 모션 블러 |
| Accessibility | UI 배율, 색맹 프리셋, 모션 줄이기, 자막 배율과 배경 |
| Controls | 리바인드, 감도, Y 반전 |

각 카테고리의 행은 추가되는 설정 수를 보여주므로 결과의 크기가 생성 후가 아니라 생성 전에 보입니다.

## 메뉴와 영속성

| 선택 | 기본값 | 영향 |
|---|---|---|
| UI 프레임워크 | 가능하면 UI Toolkit, 아니면 uGUI | 완료 단계가 어떤 메뉴 컴포넌트를 추가하라고 안내할지 |
| 영속성 | Automatic | 생성된 프로필에 기록됨 |
| 오디오 믹서 | 템플릿에서 생성 | 믹서를 생성할지 — Audio가 체크된 동안만 표시 |

`Automatic`은 WagSave가 설치되어 있으면 WagSave로, 아니면 PlayerPrefs로 해석되므로 보통 여기서 고를 것이
없습니다. `PlayerPrefs`는 WagSave가 있는 프로젝트에서도 단순 스토어를 강제합니다.

### 오디오 믹서

볼륨 슬라이더는 구동할 노출된 파라미터가 있는 `AudioMixer`가 필요하고, 파라미터 노출은 사람들이 놓치는
단계입니다. 그래서 셋업은 **믹서 템플릿** — `MasterVolume`, `MusicVolume`, `SfxVolume`이 노출된 Master, Music,
SFX 그룹 — 을 포함하고 생성 폴더에 `WagSettingsMixer.mixer`로 복제합니다.

템플릿, 생성되는 오디오 설정, `AudioMixerApplier`의 기본 버스는 일치하도록 작성되었고 테스트가 이를 묶어
둡니다. Audio Mixer Applier를 추가하고 생성된 믹서를 할당하면 모든 기본 버스가 손으로 입력하지 않아도 설정과
파라미터를 찾습니다.

**Use an existing mixer**는 아무것도 쓰지 않습니다. 믹서는 당신의 것입니다. 거기에 `MasterVolume`, `MusicVolume`,
`SfxVolume`을 노출하거나, 어플라이어의 버스 이름을 이미 노출된 것으로 바꾸세요. 믹서를 고르지 않고 이것을
선택하는 것은 Generate가 거부하는 것 중 하나입니다.

복제본은 다른 모든 생성 에셋처럼 추적됩니다. 재실행은 건너뛰고, 믹서 창에서의 편집은 유지되며, 이후 패키지
버전의 더 새로운 템플릿은 업데이트로 표시됩니다 — 손대지 않은 복제본에만 적용됩니다.

`AudioMixer`에는 공개 생성 API가 없기 때문에 빌드가 아닌 복제입니다. 템플릿은 한 번 작성되어 커밋되었고
패키지는 그것을 복사할 뿐입니다.

## 거부되는 것과 그 이유

다음 중 하나라도 해당되는 동안 Generate는 비활성화되고, 충족되지 않은 **모든** 이유가 버튼 위에 나열됩니다.

- **UI 프레임워크** — 패키지가 설치되지 않은 채 uGUI 선택. 메뉴를 열 수 없습니다.
- **카테고리** — 아무것도 선택하지 않거나, Input System 없이 Controls 선택.
- **오디오 믹서** — "기존 믹서 사용"에서 믹서를 고르지 않음.
- **프로젝트** — 블로커. 즉 생성할 것이 전혀 없음.

영속성은 절대 거부하지 않습니다. `Automatic`은 이미 PlayerPrefs로 폴백합니다.

모든 에셋이 최신이어서 미리보기가 할 일이 없다고 할 때도 Generate는 비활성화됩니다.

## 미리보기와 생성

**무슨 일이 일어날지 정확히 보기 전까지 아무것도 기록되지 않습니다.** 미리보기는 모든 에셋과 그것이 받게 될
것을 나열하고, 선택을 바꾸면 갱신됩니다.

![Generate가 만들고, 갱신하고, 유지할 것을 나열하는 미리보기](../Images/setup-preview-plan.png)

```
Into Assets/WagSettings/Resources

Create   Assets/WagSettings/Resources/AudioMaster.asset
Update   Assets/WagSettings/Resources/WagSettingsProfile.asset
Skip     Assets/WagSettings/Resources/AudioMusic.asset  (already up to date)
Keep     Assets/WagSettings/Resources/AudioSfx.asset  (edited since it was generated)
```

Generate 버튼 옆의 한 줄 요약은 항상 보이므로 상세 내용은 원할 때까지 접어 둘 수 있습니다.

### 재실행은 안전함

셋업은 생성한 모든 에셋과 기록한 내용의 지문을 담은 **생성 매니페스트**를 유지합니다. 이를 통해 세 가지 경우를
구분할 수 있습니다.

| 상황 | 일어나는 일 |
|---|---|
| 에셋이 존재하지 않음 | **Create** |
| 셋업이 만들었고 아무도 손대지 않음 | 설정이 바뀌었으면 **Update**, 아니면 **Skip** |
| 셋업이 만들었고 이후 편집됨 | **Keep** — 그대로 둠 |
| 그 경로에 이미 다른 것이 있음 | **Keep** — 셋업이 덮어쓸 것이 아님 |

따라서 카테고리를 추가한 뒤 다시 생성하면 새 에셋만 만들어집니다. **생성된 기본값을 손으로 조정한 것은 절대
버려지지 않습니다.** 생성된 에셋을 삭제하면 셋업이 다시 만들 것을 제안합니다.

### 생성이 실패하면

생성은 하나의 `AssetDatabase` 트랜잭션으로 실행됩니다. 도중에 무언가 예외를 던지면, 그 실행에서 만들어진 모든
에셋은 오류가 드러나기 전에 삭제됩니다 — 반만 생성된 프로젝트는 아무것도 없는 것보다 나쁩니다. 트랜잭션은
`finally`에서 닫히므로 실패가 세션 나머지 동안 에셋 데이터베이스를 멈춰 둘 수 없습니다.

생성된 에셋은 `Undo`에 등록되므로 <kbd>Ctrl</kbd>+<kbd>Z</kbd>가 동작합니다.

### 생성 폴더가 Resources 폴더인 이유

`Assets/WagSettings/Resources`는 이름의 우연이 아닙니다. Resources 폴더의 `SettingsProfile`은
`WagSettingsBootstrapper`가 시작 시 찾는 것이므로, 셋업을 실행한 프로젝트는 어떤 씬에도 아무것도 두지 않고
실행 중인 `WagSettingsManager` — 그리고 동작하는 정적 API — 를 얻습니다. 생성된 프로필에는 **Is Default**
플래그가 있어 같은 폴더에 다른 프로필이 있어도 우선합니다. 에디터 기록인 생성 매니페스트는 빌드에 포함되지
않도록 표시됩니다.

### 실행 후

에디터는 **Summary**로 이동하여 기록된 것을, 생성된 프로필, 생성 폴더, Quick Start 씬, 치트시트로 가는 버튼과
함께 보여줍니다. 직접 해야 할 남은 단계는 그 페이지의 문서 창에 있어 언제 돌아와도 그대로 있습니다. 조정하고
다시 생성하려면 Setup으로 돌아오세요.

![생성 후의 Summary 페이지와 바로가기 버튼](../Images/summary-after-generate.png)

## 아직 생성되지 않는 것

셋업은 **설정 에셋, 이를 담는 프로필, 오디오 믹서**를 생성합니다. InputActionAsset을 만들거나 시각적 스타일
프리셋을 적용하지는 아직 않으므로 그에 대한 컨트롤은 표시되지 않습니다. `StyleRule` 규칙, `WiringRule`의 입력
액션 절반, 그리고 그 모델 필드는 생성이 이를 지원할 때를 위해 준비되어 있습니다.

당분간 입력 액션은 손으로 배선하세요. [컨트롤](Settings/Controls.md)을 참고하세요.

## Setup으로 가는 방법

| 경로 | 시점 |
|---|---|
| **Tools → WaggleBum → WagSettings → Setup** | 언제든 — Setup 페이지로 에디터를 엶 |
| 에디터 레일의 **Setup** 페이지 | 에디터가 열려 있을 때 |
| Scene 뷰 오버레이 | Scene 뷰의 오버레이 메뉴에서 "WagSettings" 활성화 |
| 자동으로, 한 번 | 설치 후 에디터가 처음 로드될 때 |

### 스스로 열리는 것에 관하여

셋업은 **한 번** 스스로를 제안하고 다시는 하지 않습니다. 도메인 리로드마다 창을 다시 여는 에셋은 제거되므로,
답은 나타나는 순간 기억됩니다 — 즉시 닫아도 제안된 것으로 칩니다.

이 표시는 패키지 버전별로 저장되므로 메이저 업그레이드 시 한 번 더 자기소개를 할 수 있습니다. 버전을 판단할 수
없으면 전혀 스스로 열리지 않습니다. 기록할 수 없는 버전은 리로드마다 묻는 것을 뜻하기 때문입니다.

Scene 뷰 오버레이는 **기본적으로 숨겨져** 있습니다. 누군가의 Scene 뷰에 영구히 자리 잡는 패키지는 선을 넘은
것입니다. 원하는 사람을 위해 오버레이 메뉴에 있습니다.

## 구성 방식

페이지들은 하나의 `SetupSession` 위의 셸이며, 공유되므로 Summary와 Setup을 오가도 스캔도 선택도 잃지
않습니다. 프로젝트가 가진 것은 `EnvironmentDetector`, 선택한 것은 `SetupModel`, 생성 가능 여부는 `ISetupRule`
목록 위의 `SetupValidation`, 기록될 것은 `SettingsGenerator` — 모두 에디터 창 의존성이 없는 평범한 클래스이므로
모든 규칙이 직접 테스트됩니다.

규칙은 `IsSatisfied(model, out reason)`에 답합니다. UI를 소유하지 않으므로 Generate 버튼을 회색으로 만드는 같은
조건이 테스트에서는 두 줄짜리 단언입니다.

감지는 `IEnvironmentProbe`를 통해 원시 사실을 읽으므로 "지원되지 않는 에디터에서 Input System 없는 HDRP" 같은
시나리오는 프로젝트 전체가 아니라 두 줄짜리 테스트입니다. 모든 선택적 패키지는 참조가 아니라 이름으로 타입을
찾아 발견합니다. 여기서 URP나 Input System을 참조하면 셋업이 도우려는 바로 그 프로젝트에서 컴파일에 실패할
것이기 때문입니다.

Setup 페이지는 컨트롤을 다시 만드는 것과 거기서 파생되는 것을 새로 고치는 것을 분리합니다. 세션은 `Changed`와
